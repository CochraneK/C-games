## 心脏病固定房间改成「房间码 su77315 低调进入」（提交 f7cd8ed）

用户反馈上一版太扎眼：首页挂了个 banner「77 vs 315 · 专属牌桌 / 固定两个座位 / 链接永久不变」。
原话：**「这个太明显了，不要这么明显，要不就这样，有个房间就是2人的，房间邀请码是su77315」**

### 改法
1. **撤掉首页 banner**（`bell/index.html` 那个 `77 vs 315 · 专属牌桌` section 整段删除）。
2. **改成房间码入口**：大厅本来就有「已有房间码？」输入框 → 输入 `su77315` 跳
   `./duel/?room=SU77315`。`bell/app.js`（双人页）和 `bell/multi/app.js`（多人页）**两边都加了**。
3. **房间 id 换掉**：`ROOM='77315'` → `ROOM='su77315'`，
   HOST_ID = `cgames-bell-duel-v1-su77315-host`（等于换了一张新桌子）。
4. **房间页加码校验**：不带 `?room=` 直接进也放行（方便发裸链接），带错码显示 `#gate` 拦截页，
   且 `autoSeat()` 要先判 `gateOk` 否则错码也会自动入座。「复制邀请链接」拼上 `?room=SU77315`。
5. **文案中性化**：标题「心脏病 · 双人房间 SU77315」、eyebrow `TWO-SEAT ROOM`、
   brand `SU77315`、h1「两个人的牌桌。」——**「专属 / 永久 / 77 vs 315」只在房间内部和规则说明里出现**。

### 关键坑：房间码比现有正则短
现有房间码是 `/^[A-Z2-9]{8,12}$/`（8–12 位），`SU77315` 只有 **7 位**，
不单独处理会被当成「无效房间码」挡掉。**必须在正则校验之前拦下来**：
```js
const code=input.value.trim().toUpperCase();
if(isDuelCode(code)){gotoDuel();return;}      // ← 在 !ALLOWED.test(code) 之前
if(!ALLOWED.test(code)){toast('请输入 8–12 位房间码');return;}
```
URL 直进 `/?room=SU77315` 同理。

### 测试踩坑（已写进 skill）
- **stub 元素不解析 HTML 初始 class**：`makeEl()` 造出的 `classList` 是空的，
  `#gate.hidden` / `#roomView.hidden` 这些 HTML 里自带的 hidden 必须手动补，
  否则「正确房间码放行」误判 FAIL（本次 3 个 FAIL 全是这个原因）。
- 用 `Object.defineProperty(loc,'href',{get,set})` 捕获跳转才能断言导航目标。
- 测「普通码不受影响」时 `.fire('click')` 要包 try/catch —— 后面 `render()` 要真实 DOM 会抛。
- 沙箱还要补 `history:{replaceState(){}}`（bell/app.js 的 `connectRoom` 用到）。
- 相对路径断言：`location.href='./duel/?room=...'` 得到的就是 `./duel/?room=SU77315`，
  正则别写成绝对带 `bell/duel/` 的路径。
