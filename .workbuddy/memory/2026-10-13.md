## 首页「01 solo snake」元素有问题 —— 真因是非法嵌套 `<a>`（提交 76a0856）

用户说首页 01 solo snake 元素有问题。查出来两个问题，其中第一个**推翻了我 10-11 的错误结论**。

### 真因①：<a> 里嵌 <a>（HTML 非法，浏览器会自动改 DOM）
`index.html` 贪吃蛇卡片结构曾是：
```html
<a class="game" href="./snake/">          <!-- 外层卡片链接 -->
  ...
  <div class="info">...
    <div class="chips">
      <span><a href="./play.html?mode=ladder">地铁晋级赛 ↗</a></span>   <!-- 内层链接，非法 -->
```
HTML 规范禁止 `<a>` 嵌套交互式内容。浏览器解析时会**自动提前闭合外层 `<a>`**，结果：
- 卡片被拆成两段，`.info` 被甩到外层 `<a>` **外面**；
- 锚点数量变多（3 张卡片 → 4 个 anchor）。

**这正好解释了用户 10-11 贴给我的那段片段**：「4 个 anchors + `.info` 在 `<a>` 外面」。
我当时只 grep 源码、没找到该结构，就判断成「浏览器缓存的旧 Pages / 另一个站」——**判断错了**。
那段片段是**浏览器修正非法 HTML 后的渲染 DOM**，源码里当然搜不到字面匹配。

### 修复
- 内层 `<a>` → `<span class="chip-link" data-go="./play.html?mode=ladder" role="link" tabindex="0">`；
- 末尾加 JS：`click`/`Enter`/`Space` 时 `location.href=data-go`，并 `preventDefault()+stopPropagation()`
  （不阻止冒泡会连带触发外层卡片的 `./snake/` 跳转）；
- 补 `.chip-link` CSS（可点击光标、hover 下划线、`:focus-visible` 描边，保留键盘可达性）。
- 结果：`<a class="game">` 恰好 3 个（snake/bell/turtle），各自闭合，**零嵌套**。

### 真因②：标签过时
`01 · SOLO` 是上一轮加联机之前的文案，贪吃蛇现已支持多人联机+语音 → 改成 `01 · 单人 · 联机`；
chips 补「2–8 人联机」「语音可选」，描述也同步。

### 教训（跨项目，已写入用户级 MEMORY.md）
- **用户贴的是「浏览器渲染后的 DOM」，不是源码。** 遇到「源码里搜不到这个结构」时，
  先想「浏览器会不会自动修正了它」——嵌套 `<a>`、嵌套 `<form>`、`<p>` 里放块级元素、
  `<table>` 里放错标签，都会被浏览器静默改写，导致 DOM ≠ 源码。
- 不要仅凭「源码 grep 不到」就断言「不是本仓库的 / 是缓存」。

### 遗留（未改，待用户决定）
`.cards` 是 `grid-template-columns:repeat(2,...)` 两列，但现在有 3 张卡片 →
第 3 张（海龟汤）单独落在第二行左侧，右侧留白。可选：改 3 列、或让第 3 张跨两列、或补第 4 张卡。
→ **已于本日解决**：新增「一起看」卡片，凑成 4 张 = 2×2 整齐。

## 「一起看视频」（B站同步观看）可行性调研 + 落地（提交 8a29f85）

用户问：想一起看在线视频（比方 B站），一方暂停另一方也暂停，还能讨论区讨论，能实现吗？

### 调研结论：B 站做不到「硬同步」
- **B 站没有对外公开的 IFrame Player API**（不像 YouTube 有官方 API）。
- 跨域 iframe 受同源策略限制，父页面不能直接操作内部播放器。
- 社区逆向的 `postMessage` 方案**消息格式都不统一**（搜到 `{command:'pause'}` / `{type:'pause'}` /
  `{cmd:'pause'}` 三种说法）→ 说明是未公开实现，随时可能失效。
- 就算能暂停，还有**漂移**：各人缓冲不同，播着播着就差开；要维持对齐得反复 seek，反而打断观看。
- 部分视频 UP 主禁止嵌入。
- （B 站自己有「一起看」放映厅；做在我们站里的意义是能开麦 + 自定义房间 + 讨论区。）

### 用户选择：做真硬同步（换视频源）
关键洞察——**换成自管 `<video>` 元素后，源即使是跨域 mp4 直链也完全可控**：
`<video>` 在我们自己的 DOM 里，`pause()` / `play()` / `currentTime` 随便调，同源策略管不着
（`<video src>` 播放不需要 CORS）。这才是「一方暂停、另一方真的停」的关键。

### 实现（新建 `watch/`，index.html + style.css + app.js，复用 turtle 的 PeerJS 房主授权模式）
- **同步协议**：房主是真值源，每秒心跳广播 `{paused, t, ts}`；接收端用 `ts` 补偿网络延迟
  （`target = paused ? t : t + (now - ts)/1000`）。
- **漂移校正**：偏差 >0.45s 直接 `currentTime=target`；0.12~0.45s 用 `playbackRate`
  微调（落后 1.06 / 超前 0.94），比硬跳平滑。
- **任何人操作都同步全体**：成员发 `{type:'ctl', paused, t}` → 房主 apply 后广播。
  `applyState()` 期间置 `syncing=true`（120ms）抑制回环，否则 A 的操作会引发 B 再广播造成抖动。
- **视频源**：支持 mp4/webm 直链（所有人加载同一 URL）或**本地文件**
  （各自选同一个文件 → `URL.createObjectURL` → 按时长校验，差 >2s 给提示）。
  本地文件模式很实用：无带宽压力、各自从磁盘读、只同步时间戳。
- **讨论区** + **WebRTC 网状语音**（复用 turtle/bell 的 mesh）。
- 新成员加入时房主补发 `src` + `state`，进来就能对齐。

### 顺带解决首页布局
加第 4 张卡「04 · 一起看」→ 两列网格 3 张失衡变 **2×2 整齐**。
（新增卡片沿用 chip-link 规范，未在卡片内嵌 `<a>`。）

### 自检
- `node --check watch/app.js` SYNTAX OK。
- DOM id 交叉核验：app.js 引用 24 个 id，index.html 定义 26 个，零缺失。
- 首页结构核验：4 张 `<a class="game">` 开闭严格交替（78→91 / 92→106 / 107→122 / 123→147），零嵌套。

### 踩坑
- 写「检测嵌套 `<a>`」的 node 脚本时，**CSS/JS 注释里的字面量 `<a class="game">` 会被正则匹配进去**
  （真实 4 个 + 注释 2 个 = 6），且末尾 `indexOf('</a>')` 返回 -1 会导致 `idx=3` 死循环被 SIGTERM。
  → 校验 HTML 结构要用行号 + 开闭配对（Grep 看行号），别只数正则匹配次数。

## 心脏病「77 vs 315」永久两人牌桌（提交 4fb23e1，bell/duel/）

用户要：给心脏病游戏做一个**两人永久房间**，座位分别是 77 和 315。

### 设计核心：座位永久绑定 vs 角色动态分配（两者解耦）
之前 `bell/multi/` 是「房间码 + 昵称 + 谁先来谁坐 0」，座位随加入顺序漂移。
永久牌桌要求相反：**座位是固定的名字，不能因为谁先打开而变化。**

解法是**把「座位号」和「房主/客人角色」彻底拆开**：
- 座位号 `SEATS=['77','315']`，**座位号 == 游戏玩家索引**（`Core.create(kind,2)` 的 index）；
- 角色抢注决定：`new Peer(HOST_ID)`，PeerJS 固定 id 写死
  `cgames-bell-duel-v1-77315-host`；抢到即房主（裁决端），抢不到（`unavailable-id`）
  自动降级为客人去连这个 id。
- 所以：315 先打开 → 315 是房主，但**仍然坐在座位 1**；77 后到坐 0。
  先手永远是座位 0 = 77，与谁当房主无关。

### 关键实现点
- **6 秒加入超时**：房主关页面后 PeerJS 服务器上 id 会残留一会儿，客人连上去会一直挂起
  不返回 `open`/`close` → 6s 没握手就 `close()` 并重新抢 id（防止卡死在「正在加入」）。
- **座位冲突**：客人 join 带 `seat`，房主校验座位已占 → 回 `reject`，客人端退回座位选择页
  并 `cleanupPeer()`。
- **`?seat=77` / `?seat=315`**：URL 参数直达座位，两人可以各存各的收藏链接。
- 复用 `bell/multi/core.js`（`MultiBellCore` UMD）与 `bell/multi/style.css`，只覆盖 2 列布局。
- `bell/index.html` 加了第二个 banner 入口「77 vs 315 · 专属牌桌」。

### 自检：duel-smoke.js（新增，30 项断言全过）
无头 vm 沙箱跑 `core.js` + `duel/app.js`，替身 Peer 类可 `emit('open')` / `emit('connection')`
/ `emit('error',{type:'unavailable-id'})`。覆盖：
1. 77 房主 + 315 客人完整对局（准备→开局→翻牌→抢铃→广播）
2. 315 当房主时座位顺序不变（先手仍是 77）
3. 座位冲突被拒
4. `unavailable-id` 降级链路
5. `?seat=` 直达

### 踩坑
- **Promise 微任务**：`pickSeat()` 里 `loadPeerJS().then(...)` 是异步的，同步断言
  `Peer.__registry.length` 必为 0 → 测试里必须 `await tick()`（`setImmediate`）。
  第一次跑测试就栽在这里（报 `peers[0] undefined`）。
- 沙箱需要补 `window.addEventListener`（app.js 顶层监听 keydown/pagehide），
  否则 `loadInto(app.js)` 直接抛 `window.addEventListener is not a function`。
- 校验 CSS 类名时不要用「单个 `.selected`」去匹配，`.tab.selected` 是复合选择器，
  正则 `(^|[\s,}{])\.selected[\s,:{.>]` 匹配不到 → 会误报缺失。
