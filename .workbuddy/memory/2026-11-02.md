# 2026-11-02

## 对 su77315 固定房间做严格自查：找出 4 个真问题

用户要求「严格自我检查纠错，然后改进」。没有停在「看起来没问题」，逐项查了路径、协议、渲染、响应式。

### ① 多人页跳转 404（严重，已修）
`bell/multi/app.js` 里 `gotoDuel` 写的是 `window.location.href='./duel/?room=SU77315'`。
但**这个页面在 `/bell/multi/`**，`./duel/` 会解析成 `/bell/multi/duel/` → 404。
双人页 `bell/app.js` 用 `./duel/` 是对的（它在 `/bell/`）。
→ 改成 `../duel/?room=`。
**教训：相对路径按「当前页面所在目录」解析，不是按仓库根。多页面共用同一段跳转逻辑时最容易错。**

### ② 多人页必须填昵称才认房间码（体验 bug，已修）
`choose(which)` 里昵称校验在房间码判断之前：
```js
const nickname=cleanName(...); if(!nickname){toast('先输入你的昵称');return;}
...
code=$('joinCode').value...; if(code===DUEL_CODE){gotoDuel();return;}
```
结果：只拿到房间码的人点「加入」会被「先输入你的昵称」挡住。
→ 把 `if(which==='guest'){ code=...; if(code===DUEL_CODE){gotoDuel();return;} }` 提到昵称校验之前。

### ③ 野连接断开会把真正客人踢掉（协议 bug，已修）
`onGuestGone()` 原来不接受参数，用的是全局 `guestConn`：
```js
function onGuestGone(){ const pid=guestConn&&guestConn.peer; ... }
```
`guestConn` 只保留「最近一条连接」。同一个人开第二个标签页、或有人扫到链接连一下就断，
那条野连接关闭时会读到 `guestConn` = 真正客人的连接，**把真正客人的座位清掉**。
→ 房主侧改成按连接记账：`let conns=new Set()`，`fromGuest(c,d)` / `onGuestGone(c)` 都带连接参数，
`broadcast` 遍历 `conns`。关闭/出错用 `c.__gone` 防重复清算。
→ 新增测试 [10]：野连接 fire('close') 后 315 座位仍在、消息仍被处理、广播仍能到达。

### ④ 内联 style 盖掉媒体查询（响应式，已修）
duel 页为了两列牌桌把 `.play-card` 覆盖成 `width:min(100%,132px)`，
但内联 `<style>` 在 `<link>` 之后 → 连 `style.css` 里 `@media(max-width:720px){.play-card{width:72px}}`
和 `360px` 那档一起盖掉，小屏牌会撑出格子。
→ 覆盖时把两档断点补回来。

### 其他小修
- 客人点座位到房主回执之间，自己的座位会显示「空着，等人来」→ `pickSeat` 先乐观占位，
  `reject` 时把两边座位清空（否则回选座页再选另一边会残留「已坐下」）。
- 牌桌上自己的座位显示「轮到 TA 翻牌」→ 改「轮到你翻牌」。
- `?room=SU77315&seat=315` 的说明文案原来写成「或 &seat=315」，改成「把最后的 77 换成 315」。

### 测试从 41 → 55 项
新增：渲染文本断言（名单/牌桌真的出现 77 与 315、轮到谁）、
**JS 跳转路径静态审计**（解析 `location.href='...'` 到文件系统，直接抓 ①）、
被拒后清空占位、野连接隔离。

### 通用教训
- 「自查」要按**维度**过：路径 / 协议 / 渲染 / 响应式 / 文案，每个维度单独找证据，
  不要只看「我记得我写对了」。
- 静态审计很便宜且有效：把所有 `location.href='...'` 按页面目录解析一遍，5 行代码就能抓出 404。
- 测试 harness 的 stub 不解析 HTML 初始 class，也不累积 `textContent` —— 后者改造后
  才能断言「渲染出来的字对不对」，比只断言内部状态更接近真实。
